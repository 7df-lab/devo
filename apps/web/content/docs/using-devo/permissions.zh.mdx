Permissions 控制 Devo 哪些工具可以不询问直接运行，哪些必须先获得 approval。

没有显式配置时，新会话默认使用 **Full Access**，shell sandbox 为 **off**。
工具不会弹出审批，并使用当前用户可访问的文件系统和网络；这不会赋予 root 或管理员权限。
请仅在可信的工作区和任务中使用这一默认值。

Desktop 权限选择器和 TUI 的 `/permissions` 命令目前隐藏，但项目配置与 Native
`session/metadata/update` API 仍然有效。Desktop 新聊天继承服务端解析后的设置，
不会用隐藏控件的默认值覆盖项目权限。

## Presets 与 sandbox profiles

| Preset | 无需审批的操作 | 审批行为 | 默认推导的 shell sandbox |
| --- | --- | --- | --- |
| Default | 读取、编辑工作区文件，以及符合策略的工作区 shell 命令。 | 敏感请求询问用户。 | `workspace` |
| Auto-review | 与 Default 相同。 | 符合条件的请求先由自动审查器处理；不确定或失败时询问用户。 | `workspace` |
| Full Access | 按 full-access 策略允许工具请求。 | 不弹出审批。 | `off` |

审批策略与 OS sandbox 是两个独立控制项。新会话中，项目 `permission_preset`
优先于 Full Access 默认值。Sandbox 的优先级为：项目 `sandbox_profile`、全局
`[permission].sandbox_profile`、preset 推导值。因此 Full Access 可以与显式 sandbox
配置同时生效。`workspace` profile 限制文件写入，但自身不阻断网络；网络审批属于另一层策略。

`read-only` 是 sandbox profile，不是 permission preset。旧的 `read-only` preset
会映射为允许 shell 命令的 `default`。

恢复会话沿用已保存的设置，不替换为新会话默认值。修改会话 preset 会重新推导 sandbox；
同一次设置更新中的显式 `sandboxProfile` 优先。

## 非交互 prompt

`devo prompt` 使用相同的新会话默认值，并保留项目、全局 sandbox 配置。
它没有交互审批控制器：如果项目显式选择 `default` 或 `auto-review`，命令会在初始化
provider 或执行工具之前明确报错，不会静默绕过该策略。此类项目请使用交互命令 `devo`。
没有显式配置的非交互流程继续使用 Full Access，不启用 OS shell sandbox。
无效配置也会报错，不会回退到宽松默认值。

## Approval Prompts

Devo 需要 approval 时，bottom pane 打开标题为：

```text
Permission approval required
```

Prompt 包含 action summary，可能还包括：

- reason；
- resource；
- path；
- host；
- target。

使用显示的选项响应：

| Option | Shortcut | Effect |
| --- | --- | --- |
| Yes, proceed | `y` | 只允许当前 pending tool execution。 |
| Don't ask again for this command in this session | `s` | 当请求支持 session scope 时，允许本 session 后续匹配请求。 |
| Don't ask again for commands that start with a prefix | `p` | 当提供该选项时，为该 command prefix 保存持久化 allow rule。 |
| Don't ask again for files under a path | `f` | 当提供该选项时，允许本 session 后续匹配的 path prefixes。 |
| Allow this host for this session | `h` | 当提供该选项时，允许本 session 后续访问该 network host。 |
| No, continue without running it | `n` | 拒绝当前 tool execution，并让 agent 继续。 |

`Esc` 取消 approval request 并打断当前 turn。

如果某次 shell 命令的 Tier1 `with_additional_permissions` 请求已经获批，但
OS sandbox 仍然拒绝，Devo 会保持 sandbox 开启并把拒绝原因返回给模型，要求
它重新申请缺失的权限。Tier1 不会静默升级为 Full Access；只有获批的
`require_escalated` 请求才会关闭 sandbox。

## Auto-review

`Auto-review` preset 使用与 `Default` 相同的基础权限，但 eligible approval requests 会先发送给 Devo 的 automatic approval reviewer。这包括 `require_escalated` 和 `with_additional_permissions`；reviewer 会看到请求层级以及具体的额外路径/网络权限。

Reviewer 可以：

- approve 明确低风险且限定在目标范围内的 actions；
- deny destructive、credential-related、privilege-escalating 或 ambiguous high-impact actions；
- 当 user intent 或 risk 不清楚时返回 uncertain。

Uncertain requests 仍会展示给你。reviewer 超时、provider 失败或输出非法时，瞬时失败最多重试一次，之后转人工。Auto-review 是减少打断的过滤器，不替代你的判断。

## 审阅习惯

批准前检查 resource 和 target：

- 文件编辑：确认 path 在预期 workspace 内。
- Shell commands：阅读确切 command target。
- Network access：确认 host 符合预期。
- Broad session approvals：确认未来匹配请求仍然安全。

如果请求让人意外，deny 并要求 Devo 解释或选择更窄 action。

## 项目权限记忆

修改 permissions 时，Devo 会在用户配置中为 active project 记录所选 preset。这样同一项目的未来 sessions 会从预期 policy 启动，不必每次重新选择。
