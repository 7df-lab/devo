每个 Devo turn 都会向所选模型发送一个 context package。它可以包含 instructions、workspace context、available skills、active goal state、conversation history、tool results 和最新 user message。

所选模型的 context window 限制了可容纳的内容。

## Context Window

Model profiles 包含 context window，并可配置 effective usable percentage。Devo 用这些值估算当前 session 的填充程度，以及何时可能需要 compaction。

TUI 可以在 status surfaces 中显示 token usage、context-window size 和 context pressure。这些数字是估算值，用来判断 session 是否已经变大。

## 会发送什么

Devo 从多种来源构建 context：

- runtime 和 developer instructions；
- discovered project instructions；
- active skill information；
- memory 和 goal context，如果适用；
- conversation history；
- tool-call 和 tool-result records；
- 当前 user turn。

## 自动压缩

即使用户只发了一句话，一轮任务也可能需要多次调用模型。每次调用前，Devo 检查已组装请求的输入估算、当前接口指定的输出额度以及最近一次用量。上一条响应的用量很低时，新返回的大段工具结果也能触发压缩。

自动压缩会原样保留发起当前任务的用户输入，以及用户在这一轮中途补充的指令。当前轮已经完成的工作，包括工具调用参数和结果，都可以进入摘要。通常会原样保留一小段近期记录，其上限取配置输入预算的四分之一和估算 20,000 tokens 中较小的值。切分点落在完整工具批次之间。并行调用尚未全部返回时，整批原样保留，包括已经返回的结果。

选中的历史会被一份摘要替换。模型用这份摘要和保留的原文继续当前轮。再次压缩时，上一份摘要会纳入新摘要。原始聊天和工具记录仍可在会话记录中查看。

### 压缩后回查原文

在持久化会话中，模型可以用 `await rlm.history.search("错误原文", kind="tool_result")` 搜索当前分支，再用 `await rlm.history.read(item_id, offset=offset)` 读取命中位置。新摘要最多附带六个可回查的工具引用。工具调用的参数和较长的原始输出按需读取，当前轮刚刚完成的调用也可以查到。分支回退后，被舍弃的记录随即退出可查询范围。

## 手动 Compaction

主动 compact 当前 session 时使用 `/compact`。

手动命令在会话空闲时运行，使用模型当前的历史。一轮任务进行中，Devo 会在两次模型调用之间按需自动压缩。

TUI 会报告 compaction lifecycle events：

- compaction started；
- compaction completed；
- compaction failed。

## Failure 和 Retry

服务端仍然拒绝请求时，Devo 可以继续总结近期保留的已完成工作，再自动重试。只有估算的历史变小才会应用自动压缩。如果仅用户原文、未完成的调用或固定指令就超过窗口，恢复仍可能失败。

摘要请求自身超限时，Devo 把选中的历史按时间顺序分块，带着上一块的摘要处理下一块。单条很长的文本工具结果也可以拆分。所有分块成功后才替换历史。中途取消、遇到无法拆分的输入或用完重试额度时，会保留最近一次完整的上下文。

## 实用建议

大型调查后，在要求 Devo 实现改动前使用 `/compact`。当更大 objective 需要跨 compaction 或 resumed turns 保持明确时，使用 `/goal`。

重要会话里，在 compaction 前用普通聊天明确关键决策。Transcript 中有清楚的 decisions 和 constraints 时，summary 更容易保留意图。
